📖 Theory

3.1 — Power System Overview

Every electronic system needs a carefully designed power supply. The robot arm uses two separate voltage levels, each with a specific purpose.

Voltages in the system:

  • 12 V DC — main supply for the servo motors. Servos are powerful actuators and need higher voltage to produce the torque required to move the arm against gravity.
  • 5 V DC — logic level for the Raspberry Pi and sensor ICs. Derived from the 12 V rail via a DC-DC step-down (buck) converter.
  • 3.3 V DC — used internally by the Raspberry Pi's GPIO and some sensors (including the AS5600 magnetic encoders).
⚡
Polarity and short-circuit hazard
Reversing the power supply polarity, or creating a short-circuit on the 12 V rail, can permanently destroy servos and the Raspberry Pi. Always double-check connections before powering on. The system uses a fused connector — never bypass it.

Why separate voltages?

Servos draw large, spiky currents when they start moving. If the servo supply and the Raspberry Pi supply were shared directly, those current spikes would cause voltage drops that could crash the Pi or corrupt data. Separate supply rails with decoupling capacitors keep the logic supply stable.

📖 Theory

3.2 — Raspberry Pi as Controller

The Raspberry Pi is a single-board computer that acts as the central controller (the "brain") of the robot arm. It runs a Linux operating system and a server program that:

  • Receives commands from the control application over a network (WebSocket) connection
  • Translates those commands into servo instructions
  • Sends those instructions down the serial bus to the servos
  • Reads back position, temperature, and load data from each servo
  • Reports status back to the control application in real time
Your PC / Laptop (Robot Arm Control App) │ │ WebSocket (TCP/IP over Wi-Fi or Ethernet) │ Port 8080 ▼ Raspberry Pi (server on the Pi) │ │ Serial Bus (UART at 1 Mbaud) │ Half-duplex, daisy-chained ▼ Servo 1 ── Servo 2 ── Servo 3 ── Servo 4 ── Servo 5 ── Servo 6 (Joint 1) (Joint 2) (Joint 3) (Joint 4) (Joint 5) (Joint 6)

What is a WebSocket?

A WebSocket is a two-way, persistent network connection. Unlike a web page that sends a request and waits for a single response, a WebSocket stays open so the application and the Pi can exchange messages continuously — ideal for real-time control where you need instant feedback on joint angles.

What is a serial bus?

The ST3215 servos communicate over a half-duplex serial bus — a single wire that is shared by all servos. The Pi sends a packet addressed to a specific servo ID; that servo responds while all others stay silent. Because it is half-duplex, transmission and reception cannot happen simultaneously.

🔢
Servo IDs
Each servo on the bus must have a unique ID (typically 1–6). These IDs are programmed into the servo's memory. If two servos share the same ID, commands intended for one will be received by both, causing unpredictable movement. IDs are configured in the app's Settings tab.
🔗
Full communication chain
Electron App (your PC) → WebSocket / JSON over TCP port 8080 (Wi-Fi or Ethernet) → Server on Raspberry Pi (receives commands, manages motion planning and safety) → UART serial bus at 1 Mbps half-duplex (daisy-chained cable) → ST3215 servo motors (6 joints). Each link in this chain adds a small but measurable latency — understanding it helps diagnose delays and dropped commands.
🔧 Software Activity

Activity 3A — Connect to the Raspberry Pi

App tab: Connection

In this activity you will establish a live connection between the control application and the Raspberry Pi running on the robot arm.

  1. Ask your instructor for the IP address of the Raspberry Pi on your lab network. It will look something like 192.168.1.xx.

  2. Open the Robot Arm Control Application and navigate to the Connection tab.

  3. In the Connection tab, either type the Raspberry Pi's IP address and port (8080) manually, or press Auto-Detect to scan the local network for the Pi automatically. The status indicator should change to show a connected state.

  4. Click Connect. Watch the status indicator — it should change from red/grey to green within a few seconds.

  5. Press Take Control. This grants you a control session — the server will now accept movement commands from your computer. The status bar should confirm you have control. Note: if someone else already has control, you will see a message indicating this.

  6. If connection fails, check: Is the Pi powered on? Are you on the same network? Is the firewall blocking port 8080? Record what you tried in the worksheet.

  7. Once connected, note the latency value displayed (milliseconds). This is the round-trip time for a message from your PC to the Pi and back.

📖 Theory

3.3 — ST3215 Serial Servos

The joints are driven by ST3215 bus servos — smart actuators that are more capable than a standard hobby RC servo. Each one contains:

  • A DC motor with a gear reduction to increase torque
  • A position sensor (magnetic encoder) that reads the shaft angle
  • A microcontroller that runs a PID loop to hold or move to a target angle
  • A serial interface to receive commands and report status

What data can you read from a servo?

Position — current shaft angle (0–4095 counts = 0°–360°) Speed — current rotational velocity Load — motor current as a proxy for torque Temperature — internal temperature in °C Voltage — supply voltage at the servo
🌡️
Thermal protection
If a servo exceeds ~70 °C it will automatically disable torque to prevent damage. This typically happens if the arm is held against a mechanical stop, or if a joint is loaded heavily for a long period. Always monitor temperature if running continuous motion sequences.

3.4 — Magnetic Position Sensors

The servo motors have an magnetic rotary encoder mounted internally. This provides an angle reading that the Raspberry Pi can use to verify the servo's position.

⚡
ESP32 End-Tool Node
At the end of the serial bus (bus ID 64) is an ESP32 microcontroller that acts as the end-effector controller. It provides: PWM outputs (for solenoids or servos), a hobby servo output (the gripper or tool servo), ADC inputs (for current and force sensing), and digital I/O. It receives commands over the same serial bus as the main joints, so no extra wiring is needed to add end-tool functionality. The end-tool controls appear in the Joint Control tab under End Tool Servo.
🔧 Software Activity

Activity 3B — Read live joint status data

App tab: Joint Control

With the arm connected, explore the live data being returned by each servo. Ensure you are connected from Activity 3A before starting.

  1. In the Joint Control tab, observe the six joint status cards. Each card shows live data from its servo: angle (°), velocity, load (%) (percentage of stall torque — a proxy for current draw), voltage (V), and temperature (°C). Record the idle values for all six joints in the worksheet.

  2. Disable torque on one joint and gently move it by hand. Watch the angle reading update in real time — the update rate is approximately 20 ms (50 times per second). Re-enable torque.

  3. Open the Settings tab and find the status watchdog interval. If the server stops sending updates for longer than this threshold, the app falls back to polling. This is what keeps the display responsive even if the network briefly hesitates.

  4. Return to Joint Control. Using the step controls, move Joint 1 by +10°. Watch the load reading change as the motor works against gravity. Record the peak load value.

📡
The angle, temperature, voltage, and load data you are reading here is transmitted over the WebSocket from the Pi to your app approximately every 100 ms (configurable). The Pi reads this from each servo over the serial bus during each polling cycle.
📖 Theory

3.5 — Open-Loop vs Closed-Loop Control

One of the most important concepts in control engineering is whether a system uses feedback.

Open-loop control (no feedback)

In an open-loop system, a command is sent and the system has no way to check whether the result was achieved. Think of a simple light timer: it turns on at 6pm regardless of whether it is already daylight.

  • Simpler — no need to measure the output
  • Unreliable — errors accumulate; disturbances are not corrected
  • Example: sending a time-based motor pulse without measuring where the joint ended up

Closed-loop control (with feedback)

A closed-loop system measures its own output and adjusts accordingly. The ST3215 servos use this internally: the target angle is the setpoint, the encoder reading is the measurement, and the motor drive is continuously adjusted by a PID controller to eliminate the error between them.

  • Accurate — disturbances (e.g. someone pushing the arm) are corrected
  • Complex — requires sensors and a controller algorithm
  • Example: the ST3215 servo maintaining a 45° position even if you try to push it away
🔁
PID Control
PID stands for Proportional–Integral–Derivative. The controller calculates an error (target − actual), then applies three correction terms: P scales with current error, I accumulates past errors to eliminate steady-state offset, D reacts to how fast the error is changing to dampen oscillation. You will explore PID in detail in Module 8.

💭 So What?

Why does this matter?

Every modern machine — from a car's engine management system to a hospital ventilator — relies on closed-loop feedback. Understanding how sensors, controllers, and actuators work together is the foundation of all control engineering.

In the robot arm you just connected to, there are multiple closed loops running simultaneously: each servo is maintaining its position against gravity and external forces while the Raspberry Pi is listening for new commands at the same time. The network connection you set up is the link that lets you, as the operator, become part of an outer control loop — giving a setpoint to the system and observing its response.

The temperature and voltage readings you recorded are not just numbers — they are diagnostic data. In an industrial setting, engineers use this data to predict when a servo is about to fail before it causes a production stoppage. This kind of condition monitoring is a major part of modern maintenance engineering.
