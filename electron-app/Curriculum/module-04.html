📖 Theory

4.1 — Human-Machine Interface (HMI)

A Human-Machine Interface is any system through which a person interacts with and controls a machine. It is the boundary between human intention and machine action.

Good HMI design makes it easy to do the right thing and difficult to do the wrong thing. For a robot arm, the HMI must give the operator:

  • Control — ability to command movement
  • Feedback — current state of the machine (angle, speed, temperature)
  • Safety — clear stop controls, warnings, and status indicators
  • Efficiency — common tasks achievable quickly without complex menus

The Robot Arm Control App as an HMI

The application you are using is a custom-built HMI for this robot arm. It provides several different control modes, each suited to a different type of task:

Pendant Control

Intuitive slider-based control. Good for manually positioning the arm or exploring the range of motion. Analogous to a traditional teach pendant in industry.

Visual Programming (Blockly)

Drag-and-drop block-based programming. Good for beginners — no syntax to learn. Creates repeatable sequences without writing text code.

G-Code Control

Text-based numeric program format, widely used in CNC machines. Good for precisely defined path sequences loaded from a file.

Joint Control

Direct numerical control of individual joint angles. Good for precise single-joint movements and for monitoring real-time telemetry.

RAPID

ABB RAPID-subset text scripting language. Good for students who need conditional logic or want preparation for real industrial robot programming.

🤖
RAPID Tab — Industrial Robot Language
The app includes a RAPID tab implementing an ABB RAPID subset — the same language used on real ABB industrial robots. Supported commands: MoveJ, MoveAbsJ, MoveJOffs, MoveLXYZ, MoveLOffs, WaitTime, SetDO, Home, GripperOpen, GripperClose, PumpOn, PumpOff. RAPID is more powerful than G-code for programs with conditional logic, and writing it is excellent preparation for real industry programming roles.
🏭
Industrial HMI context
In industry, robot arms are typically programmed using a handheld teach pendant — a physical device with a joystick and display. Our application provides the same functionality as a software pendant, which is increasingly common on modern collaborative robots (cobots) that use tablet-based interfaces.
📱
Kiosk Mode — Robot Arm Touchscreen
In kiosk mode (the touchscreen pendant mounted on the arm itself), the app launches automatically and opens directly to the Pendant Control tab. This is why the Pendant Control interface uses large, touch-friendly buttons — the design decision is driven by the hardware it runs on. The same app running on a laptop shows all tabs and defaults to a different start screen.
🔧 Software Activity

Activity 4A — Explore the HMI and move the arm with Pendant Control

App tab: Pendant Control App tab: 3D Visualisation

In this activity you will use the Pendant Control tab to move each joint and observe the arm respond in both the real world and in the 3D visualisation. Check the workspace is clear before enabling torque.

  1. In the Pendant Control tab, note that movement is in Cartesian space (X, Y, Z in millimetres), not joint-angle space. The XY jog wheel moves the arm's tool tip in the horizontal plane; the Z Up / Z Down buttons move it vertically. Set the step size (in mm) before jogging.

  2. Compare this to the Joint Control tab — there, the step presets are in degrees (1°, 5°, 10°, 45°) and each button moves only one joint. The Pendant Control tab is intended for coarser, position-oriented movement; Joint Control is for fine single-joint tuning.

  3. Ensure the arm is connected (Module 3, Activity 3A). Open the Pendant Control tab. You should see a slider for each joint.

  4. Open the 3D Visualisation tab in a second window or split your screen if possible, so you can watch both simultaneously.

  5. Enable torque and clear the working envelope. Slowly drag the Joint 1 slider from its current position to +20° and back. Observe the base rotation on the real arm and in the 3D view.

  6. Repeat for each joint in turn. Record the range of motion (minimum and maximum angle) for each joint in the worksheet table.

  7. Find the speed control slider (or input) on the Pendant tab. Set speed to 20%. Move Joint 2 to its midpoint and note how the arm moves compared to 100% speed.

  8. Set the arm to a position you find interesting. On the Stored Positions tab, save this as position slot 0 with the label Home.

  9. Move the arm to a different position. Then load position 0 and confirm the arm returns to Home.

4.2 — Programming Concepts for Robot Control

Sequential execution

Most robot programs execute instructions one at a time, in order. Move to position A, wait, move to position B, wait, repeat. This is called sequential execution. It is predictable and easy to reason about.

Event-driven programming

The control application itself is event-driven — it does nothing until something happens (a button click, a WebSocket message, a timer firing). Each event triggers a specific handler function. This is how modern graphical applications work.

🖱️
Example:
When you click the "Connect" button, a click event fires. The application's event handler opens a WebSocket connection to the Raspberry Pi's IP address. When the connection opens, a WebSocket open event fires and the status indicator turns green. All of this happens through event handlers — not through a linear top-to-bottom program.

Variables and state

A variable stores a value that can change. In robot control programs, variables track things like the current joint angle, the target position, the movement speed, and whether torque is enabled.

Loops and repetition

A loop repeats a block of instructions. Loops are used to:

  • Repeatedly poll the servo status (the Pi's server loops every ~10 ms)
  • Repeat a pick-and-place cycle many times
  • Gradually step through a list of stored positions

Conditionals

An if/else conditional lets a program make decisions. For example: if the load reading exceeds a threshold, then stop the motor. This is how safety limits are implemented in software.

🔧 Software Activity

Activity 4B — Create a program using Visual Programming (Blockly)

App tab: Visual Programming

Blockly lets you build programs by snapping blocks together — no typing required. In this activity you will create a simple pick-and-place sequence and run it on the arm.

  1. Navigate to the Visual Programming tab. You should see a blank canvas and a palette of blocks on the left.

  2. From the palette, drag a "Move to stored position" block onto the canvas. Set it to position 0 (your Home position from Activity 4A).

  3. Add a "Wait" block below it and set the delay to 1000 ms (1 second).

  4. Save a second position on the arm (position slot 1, label it Pick). Add a "Move to stored position" block set to 1.

  5. Add another Wait block (1000 ms), then a "Move to stored position" block set back to 0 (Home).

  6. Your sequence is: Home → wait → Pick → wait → Home. Before running, ensure the workspace is clear, then click Run Program. Watch the arm execute the sequence.

  7. Modify the program to repeat the Home → Pick cycle 3 times using a Loop block. Run it again and verify it repeats correctly.

  8. Use the Convert to G-Code button to export your Blockly sequence as a G-code file. Open the G-Code Control tab and paste or load the exported code — you should be able to run the same sequence from the text file. This shows that all three text-based modes (G-Code, RAPID, and Blockly's export) describe the same motion.

  9. Use the Convert to RAPID button to export the same sequence as a RAPID script. Compare the G-code and RAPID versions — note the differences in syntax while recognising that both describe the same physical movements.

💾
Use the Save Program button to save your Blockly program. You can reload it later and continue from where you left off. Saved programs are stored locally on your PC.

4.3 — HMI Design Principles

A well-designed HMI reduces errors and makes operators more effective. Key principles include:

Consistency

Controls that do similar things should look and behave the same way. If "Start" is a green button in one screen, it should be green in every screen. Users build muscle memory — inconsistency breaks it.

Feedback

Every action should produce a visible response. Clicking "Connect" without seeing any status change is confusing — did it work? The application shows a colour-coded status indicator and a latency reading for this reason.

Error prevention over error recovery

It is better to stop a dangerous action from being possible than to deal with the consequences after it happens. The torque enable/disable flow is an example: the application requires the operator to explicitly enable torque rather than having it enabled by default.

Minimise cognitive load

Operators should not need to remember information from one screen to use another. Displaying the current joint angles on every tab (not just Joint Control) means the operator always knows the arm's state without switching tabs.

🎨
Colour conventions in industrial HMI
Red = danger / fault / stop.
Green = running / safe / go.
Yellow/amber = caution / warning.
Blue = information.
These are standardised in IEC 60073. Using red for a "confirm" button or green for a "stop" button would violate this standard and could cause accidents.
📋
Five Control Modes — HMI Comparison
The application offers five ways to control the arm, each targeting a different use case:
  • Joint Control — direct per-joint jogging with step presets (1°, 5°, 10°, 45°). Best for fine positioning and diagnostics.
  • Pendant Control — XY jog wheel and Z up/down buttons with step size in mm. Best for Cartesian-space jogging on the touchscreen.
  • Visual Programming (Blockly) — drag-and-drop block programming. Best for beginners; no syntax required. Can export to G-Code or RAPID.
  • G-Code Control — text-file motion programming using G0/G1/G28/G04/M30 etc. Best for precise, repeatable motion sequences. Includes a built-in cheat sheet.
  • RAPID — ABB RAPID-subset text language. Best for students who need conditional logic or want experience with real industrial robot syntax.
When completing the HMI usability checklist, evaluate each mode on: control (can the user do what they need?), feedback (does the UI show the arm's current state?), safety (does it prevent dangerous commands?), and efficiency (how quickly can a task be programmed?).

💭 So What?

Why does this matter?

You have just done what robotics engineers do every day: used a software interface to teach a robot a sequence of movements, then had it repeat that sequence automatically. The difference between your Blockly program and an industrial robot's program is mainly scale and complexity, not concept.

The pendant control method you used is functionally identical to how industrial robots are programmed by operators on factory floors worldwide — they jog each joint to a position, save it, and build up a sequence. The Blockly visual programming environment bridges the gap between that hands-on teaching approach and writing structured code.

HMI design is a discipline in its own right. Poor interfaces have caused industrial accidents — the Three Mile Island nuclear incident is partly attributed to confusing control room layout and indicator design. The principles you reviewed (feedback, consistency, error prevention) are not aesthetic preferences; they have measurable effects on operator performance and error rates.

As you progress to later modules — particularly G-code programming (Module 9) and system integration (Module 11) — you will see how the software layers build on top of what you have used today.
