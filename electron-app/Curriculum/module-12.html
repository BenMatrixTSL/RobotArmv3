Automation Cell Design

Designing a complete robot work cell — workspace boundaries, stored positions, programs, and safe operating procedures.

🕔 75–90 min 🎯 Group: Advanced 🔌 App tabs: Dead Zones · Stored Positions · G-Code · Joint Control
Theory

What is a Robot Work Cell?

An automation cell (or work cell) is the defined physical space, equipment, and procedures that allow a robot to operate safely and productively. It includes:

🗺️ Workspace

The volume the robot can physically reach — and the subset where it is allowed to move (the operating envelope).

🔒 Interlocks

Safety mechanisms that stop the robot if a human enters the cell — light curtains, door switches, pressure mats.

📋 Program

The sequence of moves the robot follows — stored positions, G-code files, or teach-pendant recordings.

Even a small educational arm needs these elements defined. Without a clear operating envelope, the arm may strike fixtures, cables, or people.

Theory

Dead Zones — Software Limits

In the absence of physical guards, software dead zones (also called joint limits or software stops) restrict the range of motion to a safe subset. The app's Dead Zones tab lets you configure minimum and maximum joint angles for each axis.

Why this matters: The ST3215 servos can rotate beyond the mechanical clearance of the arm structure. Without software limits, you risk stripping gears, snapping cables, or causing the arm to fold back on itself.

A well-designed cell uses all three layers — defence in depth.

Theory

Teach-and-Playback Programming

The most common way to program industrial robots is teach-and-playback: an operator manually guides the robot to key positions (using a pendant or jog controls), saves each position, then the robot replays the sequence automatically.

The app's Stored Positions tab implements this. You jog each joint to the desired pose, name it (e.g. pick_above, pick, place_above, place), and store it. A G-code program then moves between them by name or by recalled joint values.

; Simple pick-and-place G-code cell program G28 ; Home all joints G01 J1=0 J2=30 J3=45 J4=0 F50 ; Move to pick_above G01 J2=45 ; Lower to pick G04 P500 ; Wait 500 ms (gripper close) G01 J2=30 ; Lift G01 J1=90 J2=30 J3=45 J4=0 F50 ; Swing to place_above G01 J2=45 ; Lower to place G04 P500 ; Wait 500 ms (gripper open) G01 J2=30 ; Lift G28 ; Return home M30 ; End program

Stored Positions Tab — Confirmed Parameters
The Stored Positions tab manages up to 100 named positions in slots 0–99. Each position has:
  • A slot number (0–99)
  • A user-defined name string (e.g. "Home", "PickAbove", "Pick", "PlaceAbove")
  • The joint angle set for all joints at that position
Use the Save from Robot button to capture the arm's current pose. Use Export JSON / Import JSON to save and restore a complete position set — this is the cell program backup workflow. Name positions descriptively rather than using slot numbers; the names appear in G-code and Blockly programs.
Worksheet

Activity — Design Your Own Work Cell

You will define a safe operating envelope, store key positions, and write a G-code program to run a repeating cycle.

  • Open the Dead Zones tab. Review the current joint limits. Sketch the physical workspace on paper and identify any areas to avoid (cables, bench edges, other equipment). Adjust limits if needed.
  • Open the Joint Control tab and jog the arm to four key positions for a pick-and-place task: Home, Pick Above, Pick, Place Above. Write down the joint angles for each.
  • Open the Stored Positions tab. Save each of the four positions with a descriptive name.
  • Open the G-Code Control tab. Write a program using the joint angles you recorded to perform one complete pick-and-place cycle. Use G04 with a dwell time at the pick and place points to simulate gripper action.
  • Run the program at 25% speed first. Check for any joint limit warnings or unexpected motion. Gradually increase to 75%.
  • Time the cycle at 50% and 75% speed. Calculate the cycle time (time for one complete pick-and-place).

  • In Settings, switch Movement Mode between PTP and Linear Cartesian and repeat the cycle time test at 50% speed in both modes. Record both times. Linear Cartesian mode will typically be slower — the server computes Cartesian waypoints to keep the tool moving in a straight line. Note this in your cycle time table alongside the path quality (use the End-Effector Trace in 3D Visualisation to compare path straightness).

🔢
Speed Units — G-code vs Blockly
Speed is expressed differently depending on which programming mode you use:
  • G-Code: the F parameter is in steps per second (e.g. G1 J2=45 F500 — 500 steps/sec ≈ 44°/sec)
  • Blockly: speed is set in degrees per second (automatically converted to steps/sec using the ratio 11.37 steps/degree)
To convert: multiply degrees/sec by 11.37 to get steps/sec. For example, 100°/sec = F1137 in G-code.

Dead Zones Tab — Confirmed Parameters
Dead zones are defined as named rectangular XYZ exclusion volumes. Each zone has:
  • A user-defined name (e.g. "TableEdge", "CableRun")
  • X min/max, Y min/max, Z min/max bounds in millimetres (Cartesian coordinates)
  • An enable/disable toggle per zone — disabled zones are ignored during path planning
When a planned move would pass through an active dead zone, the server automatically routes the path over the zone via a safe Z height. Enable the Dead Zones overlay in 3D Visualisation to see the defined volumes as coloured boxes in the 3D model.
So What?

Cell Design in the Real World

In a factory, designing a robot cell is an engineering project in its own right. It involves layout drawings (often 2D floor plans and 3D models), risk assessments (ISO 10218-2), cycle time analysis for production planning, and sign-off from safety engineers before any operator enters the cell.

The concepts you applied here — define the envelope, teach positions, write a program, time the cycle — are exactly the steps a robotics engineer follows, just with larger, faster, and more dangerous machinery.

Think about: If this arm was producing 500 parts per day, and each pick-and-place cycle takes 8 seconds, how many cycles per hour would you need? What speed setting would achieve that? Could you redesign the path to shorten the cycle time?
