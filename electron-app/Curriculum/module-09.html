📖 Theory

9.1 — Software Architecture Overview

The robot arm system has multiple software layers, each with a specific responsibility. Understanding how they relate helps you debug problems, extend the system, and understand commercial robot software.

  • Application layer (Electron app) — the user interface. Handles tab navigation, user input, and display. Written in JavaScript/HTML/CSS. Runs on your PC.
  • Communication layer (WebSocket client) — serialises commands to JSON and transmits them to the Pi. Handles reconnection and request/response matching.
  • Server layer (server on the Raspberry Pi) — receives commands, translates them into servo instructions, and manages the servo bus. The "brain" of the system.
  • Hardware layer (Serial bus + ST3215 servos) — physical actuators executing commands. Each servo has its own PID controller (see Module 8).
🏗️
Client-server architecture:
The Electron app is the client — it requests actions. The Pi is the server — it fulfils requests and reports state. This split allows the control app to run on any device on the network, not just the Pi itself. You could control the arm from a phone browser if needed.
🏗️
Software Layers
The system has five layers, each communicating with the next via a specific protocol:
  1. Electron App (UI, runs on your PC) — HTML/CSS/JavaScript, handles all user interaction
  2. WebSocket / JSON over TCP port 8080 — bi-directional, low-latency messaging over Wi-Fi or Ethernet
  3. Server on Raspberry Pi — receives commands, manages the control session, runs the kinematics solver, enforces safety checks, handles G-code and RAPID execution
  4. Serial bus interface at 1 Mbps half-duplex — daisy-chained UART cable connecting the Pi to all servos
  5. ST3215 servo hardware — internal PID loop, position/velocity/load/temperature sensors
Label each protocol boundary in your block diagram. A fault at any one layer typically produces symptoms at a different layer — understanding the stack is essential for systematic fault diagnosis.
🏷️
Request Correlation — requestId
Every WebSocket command can include an optional requestId field. The server echoes the same ID back in its response, allowing the app to match each response to the specific command that triggered it — even when status push messages are arriving between commands. This is important for reliable asynchronous communication and is worth noting when studying the WebSocket protocol: it is not a simple request-response system, but a stream of mixed push messages and correlated responses.

9.2 — G-Code Programming

G-code is a numerical control language developed in the 1950s and still the dominant standard for CNC machines and robot motion programming. It consists of lines of simple commands.

Essential G-code commands for our arm:

; G-code comment — lines starting with ; are ignored G28 ; Home all joints (move to defined home position) G01 J1=45 J2=30 F500 ; Move joints linearly, feed rate 500 units/min G04 P1000 ; Dwell (pause) for 1000 ms G01 J1=0 J2=0 F300 ; Return to zero M30 ; End of program
📟
G-Code Command Reference — Supported Commands
  • G0 J1=45 J2=30 — rapid (PTP) move to joint angles (degrees)
  • G1 J1=45 J2=30 F500 — linear interpolated move, F = feed rate in steps/sec
  • G28 — home all joints
  • G04 P1000 — dwell for 1000 milliseconds
  • M10 / M11 — tool output on / off
  • M62 / M63 — digital output set / clear
  • M30 — end of program
The G-Code Control tab includes a built-in cheat sheet panel — open it for a quick reference while writing programs. Note: G1 (linear interpolated) is slower than G0 (PTP) because the server computes intermediate waypoints to keep the tool tip on a straight Cartesian path.

G-code is text-based and file-based — programs are saved as .gcode or .nc files and loaded into the application. This makes it easy to version-control, share, and edit programs with any text editor.

🤖
RAPID Tab — ABB Robot Language Subset
The RAPID tab implements a subset of ABB RAPID — the language used on real ABB industrial robots. Supported commands:
  • MoveJ target — joint-space move to a named position
  • MoveAbsJ [j1,j2,j3,j4,j5,j6] — move to absolute joint angles
  • MoveJOffs target, dx, dy, dz — move relative to a stored position
  • MoveLXYZ x, y, z — Cartesian linear move to coordinates
  • MoveLOffs target, dx, dy, dz — linear move with offset
  • WaitTime seconds — pause/dwell
  • SetDO signal, value — set a digital output
  • Home, GripperOpen, GripperClose, PumpOn, PumpOff
RAPID is the best choice when your program needs conditional decisions (IF/THEN logic) or when the goal is to develop transferable industrial robot programming skills.
🔧 Software Activity

Activity 9A — Write and run a G-code program

App tab: G-Code Control

  1. Open a text editor (Notepad is fine). Type the following G-code program and save it as pick_place.gcode on your desktop:

    ; Pick and place sequence G28 G04 P500 G01 J1=30 J2=45 J3=-20 F400 G04 P1000 G01 J1=30 J2=20 J3=-40 F300 G04 P800 G01 J1=-30 J2=20 J3=-40 F300 G04 P800 G28 M30

  2. In the app, navigate to G-Code Control. Use the Load File button to open your pick_place.gcode file. You should see the commands listed in the preview panel.

  3. Confirm the workspace is clear and torque is enabled. Click Run to execute the program. Observe each step.

  4. Modify the program: change the feed rate (F value) on one move to 100 (very slow). Reload and run again. Observe the difference in movement speed for that step only.

  5. Add a G04 P2000 dwell at the midpoint (after the second move). Reload and run to confirm the pause is in the right place.

💡
The joint angles in the sample program are illustrative. Adjust them to match positions that make sense for your arm's geometry and saved positions from earlier modules.

💭 So What?

Why does this matter?

G-code is used in virtually every CNC machine on earth — from small desktop mills to multi-million-pound machining centres. The commands you wrote in this module are structurally identical to programs running on industrial production equipment today. If you can read and write G-code, you can communicate with CNC operators and understand their programs.

The client-server split between the app and the Pi is a fundamental design pattern used throughout industry. It means the intelligence of the control system is in the software, not wired into hardware — so you can update, extend, or replace the app without changing any hardware. This is how modern machine tools and robots are increasingly designed: the physical machine is a "dumb" server, and the smart logic runs on software that can be updated remotely.
